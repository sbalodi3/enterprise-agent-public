# What left the local demo during the audit

On November 18, 2026, a synthetic adjuster signed in, opened WC-101, reviewed its timeline, ran the replay and live Workbench assistants, selected a folder in hosted Chat and sent a message. Both assistants answered. The application page requested only the three local origins. The Workbench and Chat processes contacted only the isolated services and loopback during this run. The browser process itself also tried to contact Google. The proxy denied those connections before forwarding any request.

## Observed destinations and data

| Observation point | Evidence |

These attempts were outside the observed page-request stream. The observer recorded host and port only. The capture does not identify the contents Chrome intended to send. |

The Docker hostname `host.docker.internal` resolved to the disposable Workbench in this run. Namespace observers saw local TCP traffic, internal DNS lookups and reverse lookups for private addresses. No public destination appeared in their recorded traffic. |

The recorder saw two live requests with exactly four available tools: `compare_evidence`, `explain_priority`, `prepare_handoff` and `timeline`. The second contained the tool result. Neither request contained the synthetic architecture marker or the top-level `dsh_session_log` field. |

No recorded request contained the synthetic architecture marker or the raw provider-log field. The synthetic workspace instruction marker was also absent in this particular browser run. ## How the observation was made

1. Use the claims baseline identified in the [security audit](security-audit.md) and the enterprise launcher from this review. Start disposable PostgreSQL, Keycloak, Workbench, hosted Maya Chat and an OpenAI-compatible HTTP recorder with fresh volumes and synthetic credentials. The reference run used the locally cached `claims-workbench:local` image and mounted the reviewed launcher read-only. Mount a unique synthetic Markdown marker in a directory outside the application runtime and a separate fake workspace for Chat. Keep real employee data and credentials out of the experiment.
2. Place those services on a Docker network created with `--internal`. Use a loopback-only ingress relay with three fixed destinations for the browser. Set the containers' fallback DNS to loopback. Log only destinations for Node TCP connections and DNS calls in Workbench and Chat. In both network namespaces, record outgoing TCP SYN destinations, UDP endpoints and DNS question names. Run the packet observer separately from the application. This preserves the distinction between a requested hostname and a packet that actually left a process.
3. Start Chrome in a fresh profile with a SOCKS proxy for every origin, including loopback. Allow only the three application ports and block other destinations. Disable QUIC, direct DNS fallback and service workers. Also record request origins at the Playwright page boundary. Exercise both modes and leave the successful session idle for 32 seconds before closing. The model recorder returns a synthetic streaming tool call and answer and records marker presence and tool names, without saving the request body.
4. Compare the browser, server and receiver observations. A denied connection, a model request accepted by the recorder and a private data transfer to a third party are separate results. The existing [desktop observations](desktop-evidence.md) cover the workstation companion and stock Desktop telemetry. The [security audit](security-audit.md) includes repeatable receiver tests for upstream providers, telemetry, registry lookups and search.

This was a bounded test with an enforced network policy. The regular demo's Compose networks allow outbound connections. The run did not exercise every Chat tool, supply a vendor credential, capture historical traffic, or demonstrate that disabling analytics prevents unrelated browser or plugin traffic. The local model recorder used the OpenAI-compatible route. The official DeepSeek request extension was checked separately in its own adapter tests and in both resolved enterprise profile configurations.
