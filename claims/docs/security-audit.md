# Enterprise Agent outbound data and consent review

Reviewed November 18, 2026. The upstream comparison point is the merge of upstream PR #8278, the locally verified common ancestor of the claims branch and upstream. The enterprise baseline is the commit titled “Correct the Enterprise Agent product name” on `feat/claims-workbench`. To recover the exact commit IDs, run `git rev-parse 'HEAD^{/^Merge pull request #8278 from deepseek-harness/worktree-sync-release-dsh-0.2.2-rc.2-to-master}' 'HEAD^{/^Correct the Enterprise Agent product name}'` in the claims checkout. Findings labelled **upstream** were present at the common ancestor. Git history identifies the source revision. Individual intent is outside the evidence.

**The most consequential finding is a second session-log upload path.** Stock DeepSeek can attach an incremental copy of the canonical session log to an ordinary official-model request. This can include the working directory, user input, tool results and events outside the model's normal messages. It requires no feedback submission. The local claims model uses a different adapter. At the enterprise baseline the upload contributor was still mounted, so changing Chat to an eligible DeepSeek route could change what left the machine. The updated shared Enterprise Agent launcher explicitly disables the contributor for both Chat and Workbench. This review found documented vendor data collection and capabilities that can disclose files or prompts in specific configurations. No reviewed path established a backdoor or a prior unauthorized transfer of an actual claim or ADR. The baseline for this demo is local runtime traffic. Intentional downloads to build or install the application and distribution of the private development repository have different recipients and triggers.

## Developer, build and publication paths

The repository itself has scripts that start before a developer explicitly invokes an agent. Root `postinstall` installs Lefthook into a qualifying Git checkout. Its configured pre-commit jobs can fix and stage lint changes, and pre-push runs type checking. The lockfile's build allowlist enables native build scripts for selected packages. The nine Cordis-related vendored source packages list upstream commits and documented changes. Twelve dependency patches and the native Linux/Windows/macOS code widen the trust boundary. Both claims npm locks use integrity values for their npm registry tarballs. The one filesystem dependency is the local harness error package. Those checks constrain downloaded bytes and versions. They do not attest to the behavior of every installed package. [Install hook](../../scripts/install-lefthook.mjs#L623) · [Git hooks](../../lefthook.yml) · [Build permissions and patches](../../pnpm-workspace.yaml#L31) · [Vendor manifest](../../vendor/README.md) · [Native binaries](../../native/README.md)

The full image build contacts OS and npm registries as needed. Claims-specific npm installs use `--ignore-scripts --no-audit --no-fund`. The separate model downloader makes an explicit download from Hugging Face for a pinned revision and verifies SHA-256. A new Git remote, a remote builder, a CI checkout, release publishing, and hosted coding-agent reads are distinct ways development material can leave the workstation. The inherited PR preview workflow attempts to publish `apps/web/dist` to Cloudflare when credentials are configured. The inherited release and docs-publishing workflows have separate dispatch triggers. A developer can also publish a GIF to a GitHub PR. At the reviewed baseline the full Docker build context lacked an explicit exclusion for internal architecture notes, although its COPY commands did not select that tree. The updated Dockerfile-specific ignore files exclude development material. Verify a new builder's context and repository visibility before sending Internal documents. ## Coverage and evidence

- **Git and source.** The comparison covered 21,248 tracked paths at the enterprise baseline. Its 23 commits change 116 paths relative to the upstream common ancestor. A static scan of 7,295 tracked source/configuration/script files outside tests, snapshots, documentation and generated lock declarations looked for transport APIs, hard-coded hosts, credential/persistence access, dynamic evaluation and shell-download patterns. There were 263 transport-pattern candidates and nine dynamic-evaluation candidates. Manual review followed selected calls through the active plugin composition, request construction, destination, UI/agent trigger and tests. The nine evaluation candidates were in loader/schema code, opt-in runners/inspector, the PTC evaluator and a packaging patch. The PowerShell `Invoke-Expression` hit was the persistent shell's implementation. A check of all tracked file headers found no ELF, PE, WASM or Mach-O binary signatures; all 14 tracked symlinks resolved inside the checkout. Runtime native dependencies, container layers and downloaded model weights fall outside that tracked-file result.
- **Local receiver and synthetic tests.** Five upstream test files passed 108 tests covering stock product analytics, the OTel product exporter, session-feedback egress, feedback storage and feedback UI control. Four files passed 65 tests for the independent official-model log contribution. The latter sent a synthetic log to a loopback stand-in for the model API and exercised disabling, resumption and a failed response followed by retry. The OTel egress test establishes that a model fetch proxy alone misses the direct collector transport. These tests used synthetic credentials and fixture receivers. [Feedback egress](../../packages/session/session-telemetry-otel/tests/egress.spec.ts#L76) · [Product receiver](../../packages/client/product-analytics/tests/collection.host.spec.ts#L75) · [Official request receiver](../../packages/session/session-log-deepseek/tests/feedback-composition.spec.ts#L81)
- **Search and registry tests.** Three further test files passed 58 cases using fake request transports. They exercised inclusion and omission of the original user question, registry probe eligibility, and installed versus CDN-backed plugin detail reads. The combined result was 231 passing tests in 12 files. [Original-question tests](../../packages/web/web-deepseek-api/tests/search.spec.ts#L238) · [Registry probe tests](../../packages/client/ui-plugin-manager/tests/registry-probe.host.spec.ts) · [Plugin detail tests](../../packages/client/ui-plugin-manager/tests/detail-store.client.spec.ts)
- **Application traffic.** The [runtime evidence](runtime-evidence.md) records which full application paths were exercised, what was observed and where monitoring coverage ends. The [developer context inventory](developer-context.md) identifies which instructions and skills can become model input.
- **Artifact inspection.** The [build artifact check](artifact-check.md) records the evidence and limits for including internal documents in a source repository while excluding them from the application build.
- **Limits.** This is a targeted source and behavior review. It does not reconstruct prior network activity on an employee's machine, audit the remote services, establish author intent, or independently rebuild and verify every transitive dependency or release binary. Model selection, settings overlays, old vendor grants, enabled plugins, browser extensions, runtime image contents and network policy can change observed behavior. No live claims or partner credentials were used.

For the local demo, the strongest privacy control is to restrict outbound connections at both the host/container and browser boundaries. Keep the claims model and trace receiver explicitly local. If a service later requires external access, document the destination, exact fields and trigger for that integration. Judge consent at the point of disclosure. Choosing a model, rating its answer, opening a plugin detail and authorizing a partner evidence request disclose different data to different recipients.
