# 工资证明试点

[English](README.md) | 中文

仅使用合成案件。协调员在招募前记录核验各题答案的审核员和核验日期。核验完成前，以下答案来自合成案例。每位使用编号的参与者使用独立的浏览器配置。以模拟理赔员 Maya 登录。如果需要保留当前案件组合的统计，请在独立的演示副本中开展研究。

## 准备工作

在 Workbench 中启用 `CLAIMS_WAGE_REVIEW=1`，构建理赔镜像，并用配置好的本地模型启动演示。运行 `"${CONTAINER_ENGINE:-docker}" exec enterprise-agent-showcase-workbench-1 node claims/showcase/wage-study/seed.mjs`，载入八个合成案件。重复执行会保留已有记录。在 Workbench 打开每个案件并检查 Sources 选项卡。在独立的练习案件 WC-102 上试用一次试点按钮。基线组使用现有的 Workbench 来源和时间线。辅助组从 Workbench 中的同一位置开始，使用 **Review missing wage evidence**。两组使用相同指令：“指出请求所涵盖的期间、仍缺少的证明以及任何相互冲突的证据。出示支持答案的段落。”

## 测试安排和参考答案

招募八位理赔员。每人审核四个案件，每对选一个，每种界面各使用两次。奇数编号的参与者使用每对中的三月案件，依次使用基线、辅助、基线、辅助界面。偶数编号的参与者使用四月案件，界面顺序相反。参与者 3、4、7 和 8 互换三月与四月的分配。参与者 5 至 8 以相反顺序审核案件，各对对应的界面保持原分配。对参与者隐藏答案。五分钟超时记为未完成。公布任务时开始计时，包含推理等待时间，在首次正确判断缺口时停止计时，再要求参与者出示来源。测试过程中不提供辅导。初次判断错误即予以记录，即使后来纠正也保留。

| 配对 | 三月和四月案件 | 参考判断与来源核验 |
|---|---|---|
| A | WC-951 / WC-952 | 请求涵盖第 1 至 21 天。档案中没有工资回函。打开请求并查看文档清单。 |
| B | WC-953 / WC-954 | 第 1 至 7 天已有记录。第 8 至 21 天仍缺失。打开请求和第一份回函。 |
| C | WC-955 / WC-956 | 回函分别涵盖第 1 至 14 天和第 8 至 21 天，覆盖全部 21 个不同日期。打开请求及两份回函。 |
| D | WC-957 / WC-958 | 21 天均有记录。相同期间的税前金额分别为 1,800 和 2,100 美元，正确金额有待确认。打开两份回函和请求。 |

## 评分表

在[试点评分表](scorecard.md)中填写分配的任务和审核签署结果。逐项记录参与者编号、案件、组别、首次判断是否正确、得出正确结论所用秒数或未完成状态、预期来源段落、参与者正确打开的段落、核验的界面事实、正确的事实与段落映射，以及是否使用固定布局。仅使用合成 ID 记录这些研究字段。运行遥测中不记录身份标识或案件文本。工资审核区的 `data-layout` 属性标明布局模式。单独记录 SDK 或渲染故障。

对每位参与者分别计算两组正确完成任务的耗时中位数，再计算配对改进百分比 `100 × (baseline − assisted) / baseline`。报告配对改进值的中位数、范围和可计算的配对数量。以**所有**分配任务为分母报告首次判断的准确率和未完成数量。缺少参与者配对数据时不作扩大试点的决定。分别报告参与者成功打开来源的比例和固定布局的使用比例。配对改进中位数至少为 20%、辅助组准确率不低于基线组，且界面呈现的每项重要事实均对应正确段落，才扩大试点。判断缺口时检查请求及适用回函。判断没有证明时还须核对文档清单。如果任一条件未满足，继续通过试点开关控制 A2UI。
